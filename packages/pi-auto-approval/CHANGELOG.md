# Changelog

## Unreleased

- Bash commands with `$'...'` quoting are now matched against rules when every escape is `\n`, `\t`, `\\`, `\'` or `\"`. Any other escape still sends the whole command to review. `echo` is read-only, and so is `date` with no arguments or a single `+FORMAT` argument.
- **Breaking:** a project can now have two config files in `.pi/pi-auto-approval/`. `auto-permissions.json` is meant to be committed and may only add deny and ask rules, `enabled: true` and `reviewMode: "manual"`. `auto-permissions.local.json` is meant to stay out of git and may also set allow rules, `enabled` and `reviewMode`. Project allow rules in `auto-permissions.json` are now a validation error, so move them to `auto-permissions.local.json`. Settings and allow rules from either file apply only when the project is trusted. Deny and ask rules always apply.
- Writes and edits to the guard's own config always ask, even with a matching allow rule, and are blocked when there's no UI. Bash commands that mention `pi-auto-approval` or `auto-permissions` ask too. Paths are compared after following symlinks, ignoring letter case and Unicode spelling.
- File deny and ask rules now also match the path after following symlinks, ignoring letter case and Unicode spelling. File allow rules match only the real path after following symlinks, with letter case kept, so an allow rule that names a symlinked path may now send the call to review.
- Bash allow rules now match the command's words, not its raw text, so quoting no longer matters. Inside a rule word, `*` matches within one path segment and `**` crosses `/`. A rule word that is exactly `*` matches any number of whole words. An allow rule doesn't match if a `key=` it names appears twice, or if a path-like value contains a `..` segment. Deny and ask rules keep raw-text matching. They also match after removing a leading `env`, `command` or `exec`, match the bare command for a rule ending in ` *` (so `Bash(git push *)` matches `git push`), and match quoting-insensitively on both sides. Calls over 65,536 bytes get no allow-rule or read-only approval.
- **Breaking:** `Bash(cat src/*)` no longer matches `cat src/a/b.ts` (use `src/**`), and `Bash(git diff*)` no longer matches `git diff --stat` (use `Bash(git diff *)`). Such calls now go to review. Exact allows such as `Bash(git status)` are unchanged.
- The reviewer now judges each call against four prose lists in `reviewer`: `environment`, `allow`, `softDeny` and `hardDeny`. A list that isn't set uses the built-in defaults, and `"$defaults"` inside a list adds them. Lists merge from the global config and, only in a trusted project, from both project files. The shared `auto-permissions.json` may set only `softDeny` and `hardDeny`, and each must include `"$defaults"`. Changing a list starts a new reviewer session.
- **Breaking:** the reviewer's verdicts are now tiered, and `ask_user` is gone. `approve` runs the call. `block` with `hard_deny` blocks it with no dialog. `block` with `soft_deny` asks you, showing the reviewer's reason, and is blocked when there's no UI. `revise` names the user constraint the call breaks, and asks you or blocks the same way. An unreadable verdict gets one retry. If that also fails, the review counts as failed: you're asked, and the call is blocked when there's no UI.
- Every block returned to the agent now reads `Blocked by auto-approval (<source>): <reason>`, followed by a line telling the agent the tool didn't run and not to retry the action another way. The source is `deny rule`, `protected path`, `reviewer`, `no UI`, `user`, `config`, `error` or `cancelled`.
- The reviewer sees which paths earlier allowed writes and edits touched, but never their content.
- Each `history.jsonl` line now records `by`, the step that decided the call (`config`, `deny-rule`, `allow-rule`, `read-only`, `protected-path`, `reviewer`, `user`, `headless` or `cancelled`), and `reason`, the block message returned to the agent or the reviewer's reason for an approval. `reason` is redacted like `command`.
- The README now documents slices 1–5, and "Review and controls" item 5 is fixed: valid unsupported Bash goes to the reviewer in auto mode and asks in manual mode, and malformed input always asks.
